## 阶段 0 · 路线决策

**先回答一个问题：你要 XL330 还是飞特 HD-1910？**

| | XL330（路线 A） | 飞特 HD-1910（路线 B） |
|---|---|---|
| 优点 | 官方策略**直接跑**，机械件不用碰，风险最低<br>✅ 已有项目跑通官方 9 项策略 | **便宜一半以上**（¥123/颗 vs ¥299）<br>力矩约 2 倍（12 vs 6.1 kg·cm @6V）<br>**电压原生匹配** 2S（4–8.4 V）<br>空心杯 + 金属齿 |
| 代价 | 舵机 **¥3,600–4,500**<br>⚠️ 被**超压运行**（额定 3.7–6.0 V，实际给 6.6–8.2 V） | **必须重训策略**（要 CUDA 显卡或 HF jobs）<br>⚠️ 协议层来源冲突，**可能需改 robotd**<br>位置计数方向 15 颗全反 |
| 打印件 | CAD 仓库 v1.1 XL330 版 | CAD 仓库 v2.1 飞特版（`-FT` 后缀） |
| 舵机预算 | 15 × ¥299 ≈ **¥4,485** | 15 × ¥123 ≈ **¥1,845** |

> 💡 **决策建议**：如果你只是想先让鸭子站起来走两步、不想碰训练 —— **选 A**。
> 如果你本来就想学 RL 训练、或者预算敏感 —— 选 B，但要接受"飞特适配还没上过板"这个现状。
>
> ⚠️ **最省事的判断依据**：如果你**没有 NVIDIA 显卡**，路线 B 的策略重训这一关就过不去，直接选 A。

⚠️ **两款舵机的配合件绝对不能混用** —— HD-1910 舵盘是**凸出来**的，XL330 是**凹进去**的，所有跟舵盘配合的件都改过（8 个件）。
⚠️ **针序也相反**：XL330 = `1=GND/2=Vcc/3=DATA`；HD-1910 = `1=Signal/2=Vcc/3=GND`。好在间距不同（2.5 vs 2.0 mm）插不进对方，只剩"自己压线压反"这一种可能。

**✅ 验收**：写死一个选择，记下来。后面所有打印、采购、软件分支都跟它走。

| 项 | 值 |
|---|---|
| 打印机 | Bambu Lab **P2S**，0.4 喷嘴 |

> ⚠️ **仿真 STL ≠ 可打印工程件。** 仿真只保证外形与惯量，**不保证配合公差、螺纹孔、热熔螺母座、走线空间**。

**打印后第一件事：卡尺抽查关键孔径**（尤其舵机输出轴和法兰配合位）。FDM 收缩**通常偏小 0.1–0.3 mm**，孔径偏小要扩孔或重打。

**⚠️ 别搞混左右**：`upper_leg_left/right`、`ankle_left/right`、`sole_left/right`、`foot_left/right`、`hip_l` 都是镜像件，**两个都要打**。

**✅ 验收**：
- [ ] 35 项件全部齐（走路只需 1–27 + 31–35）

## 阶段 3 · 舵机预配置 ⚠️ 必须在机械装配之前

> **这是最容易做错顺序的一步。** 舵机装进结构件之后再改 ID/校准，要全拆。

### 3.1 需要什么

- HD-1910-C001 × 15（**出厂 ID 全是 1**）
- **FE-URT-2 调试板** + USB-C 线 + 飞特 FD 软件（`参考资料` 仓里 `tools/飞特/`）
- 一根**剪开的舵机线**（调试板口跟舵机 2.0 mm 线插不上，15 根牺牲一根）
- 万用表 · 标签纸

### 3.2 飞线（认脚号，别认颜色）

```
舵机线                    FE-URT-2
脚 1  Signal  →  S    焊到板背面白口 S 脚焊点上
脚 2  Vcc     →  V1   蓝色接线端子
脚 3  GND     →  G    蓝色接线端子
```

- **中间那根一定是 V** —— **V 接错才会烧**；S/G 接反不烧，只是搜不到，对调即可
- ⚠️ **上电顺序：先插 USB，再给舵机上电。** 反了总线会被压在 2.1 V，一颗都不应答（曾在这耗一小时）
- 板上拨码是 **TTL 信号电平（3.3/5 V）** 选择，**不是供电切换** → 拨 5 V

### 3.3 软件

1. 插 URT-2 → 设备管理器出现 `USB-Enhanced-SERIAL CH343 (COMx)`（Win10/11 免驱）
2. 解压 `FD1.9.8.5(250729).7z` 直接运行
3. FD 里选 COM 口 → **波特率选 `1000000`** → 打开
4. ⚠️ **型号显示 `unknown` 不用管** —— FD 版本旧认不出 HD-1910，但寄存器读写完全正常

### 3.4 配 ID：一次只接一颗

> ⚠️ **飞特出厂 ID 全是 1。15 颗一起接上去全都应答，分不出谁是谁。**

**ID 对照表**（来自官方 `duck-control/src/model.rs`）：

| ID | 关节 | ID | 关节 | ID | 关节 |
|---|---|---|---|---|---|
| **10** | 右髋 yaw | **20** | 左髋 yaw | **30** | 颈俯仰 |
| **11** | 右髋 roll | **21** | 左髋 roll | **31** | 头俯仰 |
| **12** | 右髋 pitch | **22** | 左髋 pitch | **32** | 头 yaw |
| **13** | 右膝 | **23** | 左膝 | **33** | 头 roll |
| **14** | 右踝 | **24** | 左踝 | **34** | 嘴 |

**记法**：十位 = 部位（**1 右腿 · 2 左腿 · 3 颈头**），个位 = 从躯干往末端数（**0 髋 yaw → 4 踝**）。
ID **200** 是 `imu_to_dxl` 板，固件里写死，不在这里配。

### 3.5 每颗都改这几项（切到「编程」页 EPROM）

| 参数 | 出厂 | 改成 | 为什么 |
|---|---|---|---|
| **ID** | 1 | 按上表 | 官方运行时按这个 ID 找关节 |
| **过流保护** | 关 | **开** | 装机后堵转是常事，不开就是烧舵机 |
| **过压保护** | 关 | **开** | 8.4 V 满电落在窗口内，不会误触发 |
| 过热保护 | 开（80℃） | 不动 | — |
| 波特率 | 1 Mbps | **不动** | 出厂就是官方要的 |
| 运行模式 | 模式 4 纯位置 PD | **不动** | 正是强化学习落地要的那个 |
| 中位 | — | **装机后再校** | 见阶段 8 |

改完点「保存」→ **断电重启 → 再搜一次，新 ID 出现了才算写进去**（EPROM 要断电才确定）。

**⚡ 然后贴标签**：写**关节名 + ID**（如「左膝 23」），**别只写数字** —— 15 颗长得一模一样。一颗约 2 分钟。

**⚠️ 电池满电 8.4 V 正好等于 HD-1910 电压上限**，零余量 → **别在满电电池上做堵转测试**。

**✅ 验收**：15 颗全部配好 ID、开好保护、贴好标签，单独上电都能转到中位并回读角度。

## 阶段 4 · 机械装配

### 4.1 装配顺序：**01 → 15 按编号**

```
1.  01           躯干主体 —— 整机基准，先行固定
2.  02 → 06      左腿   左髋 → 左髋 Roll → 左大腿 → 左小腿 → 左踝脚
3.  07 → 10      颈头   颈根 → 颈俯仰 → 头 Yaw/Roll → 头部总成
4.  11 → 15      右腿   右髋 → 右髋 Roll → 右大腿 → 右小腿 → 右踝脚
```

**这个顺序几乎是强制的**：线缆要从躯干一路穿到末端，先装末端会导致反复拆装。
每一步的配图与详细步骤见 [装配安装说明书 PDF](../hardware/microduck装配安装说明书.pdf)（21 页）+ `../hardware/组件图/`（23 张）。

### 4.2 通用守则（摘自说明书）

- 装配前对照 BOM **清点零件数量与规格**，确认 M2/M2.5 螺丝齐全
- **舵机类关节件：装配前先通电归中位再锁紧**，避免行程偏移
- 螺丝**对角分步预紧**，避免单边受力导致零件变形；**塑料件切勿过度锁紧**
- **左右对称件务必区分左右，切勿装反**
- 线缆统一固定、**预留关节活动余量**，严禁压线、夹线、缠绕
- **每装完一个活动关节就转动测试一次**，检查干涉、卡滞、异响
- 首次通电前检查所有电气连接、绝缘与极性

### 4.3 两个建议增强

| 件 | 说明 |
|---|---|
| `neck` / `trunk_base` / `upper_leg_rigidity_plate` / `bearing_roll` | 可换**铝合金**增强强度 |
| 飞特版结构改进 | [fengj4780-sudo/MICDUCK_FTHD1901_REBUILD](https://github.com/fengj4780-sudo/MICDUCK_FTHD1901_REBUILD) 加强薄弱件、修装配干涉；**腿部 5 件可换 CNC**（5 件含运费约 ¥45） |

### 4.4 热熔螺母

⚠️ **必须用专用烙铁压头**（M2–M8 套件 ¥13），普通烙铁头压不正、会歪。

**✅ 验收**：
- [ ] 15 个关节每一个都手动转动过，无干涉/卡滞
- [ ] 左右件方向正确（髋 pitch、膝是镜像的）
- [ ] 线缆有活动余量，过颈的舵机总线 + 电源线不被拉扯
- [ ] M2 螺丝对角预紧到位，塑料件无过紧变形

## 阶段 5 · 电控（两条路，选一条）

### 路线 5A · 打官方 HAT 板（功能最全）

**官方 Gerber/BOM/坐标在 `elec_RPI_Robot_HAT` 的 `production/`**，直接送嘉立创。

| 项 | 值 |
|---|---|
| 层数 / 板厚 | **4 层** / **1.0 mm** |
| 尺寸 | 65.0 × 30.9 mm |
| 元件 | 47 行 / 123 颗（9 颗 DNP） → 实际 113 个位置 |
| ⚠️ | **必须选 SMT 服务**，含 VQFN-32 和 LGA-16，手焊不可能 |
| ⚠️ | 打开 KiCad 前先装 `lib_KiCAD`（只打样不用） |
| ⚠️ | **这块板没有充电电路也没有 USB-C 输入**，电池要外部充电器充 |

**板子装在哪（最容易搞错的一条）**：
```
头（jaw_soft 刚体）
 ├── Radxa Zero 3W 主控     ← 主控在头里，不在躯干！
 ├── RPI Robot HAT           ← 叠在主控上方 7.3 mm
 ├── IMX219 摄像头 + M12 镜头 ← 距主控约 13 mm，同一刚体
 └── 喇叭

躯干（trunk_base）
 ├── 两颗 hip_yaw 舵机
 └── NP-F550 电池（外挂在机身后下方，约 40 mm 悬在壳体外）
```

### 路线 5B · 不打 HAT，¥70 飞线（推荐先走这条）

> 官方 HAT 是 4 层板双面贴装 110 个器件，打样贴片一次上千块。**替代方案：一个降压模块 + 一个半双工转接板。**
> **只少板载音频和关机检测信号。**

**要买**：UBEC 5V/3A（¥10–15）+ 半双工转接板（¥22）+ 2×20 排针 + 18AWG 硅胶线 + 5A 保险丝座 + 船型开关 + 470 µF 电容

**接线**：
```
NP-F550 ─► 开关 ─► 保险丝 5A ─┬─► 降压模块 ─► 5V ─► Radxa pin 2（或 4）
                              │        └── 输入端并 470 µF
                              └─► 舵机总线 VDD（原压，18 AWG）
共地：电池负极 · 降压输出地 · Radxa pin 6 · 舵机总线 GND
```

```
Radxa 40 针                 转接板 MCU 侧
pin 1   3.3 V  ────────►   VCC   ⚠️ 只能 3.3 V，接 5 V 它的 TX 会打坏主控 RX
pin 8   UART2_TX ───────►  RX    ← 交叉
pin 10  UART2_RX ◄───────  TX    ← 交叉
pin 6   GND    ────────►   GND
```

**总线分支**（半双工单线总线是**并联**不是链，星形树形都通）：
```
转接板 TTL ─┬─► 头颈  30 → 31 → 32 → 33 → 34
            ├─► 左腿  20 → 21 → 22 → 23 → 24
            └─► 右腿  10 → 11 → 12 → 13 → 14
            （imu_to_dxl 200 挂躯干里任一路）
```

**⚠️ 飞线段已知翻车点**：

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 转接板逻辑供电取 5 V | 它的 TX 会用 5 V 电平打进主控 3.3 V 的 RX | **从 pin 1 取 3.3 V**；ToF 从 pin 17 取，两个不抢 |
| 5 V 灌进 40 针 | **绕过板载 USB 输入保护，接反当场烧板** | 插之前先量降压模块输出的极性和电压 |
| 舵机主干用杜邦线 | 24–28 AWG 只扛 1 A，会发烫熔皮 | **主干用 18–20 AWG 硅胶线** |
| 电池到舵机裸接 | 锂电池短路会喷火 | **串 5 A 保险丝 + 电源开关** |
| 三路电流全走 `imu_to_dxl` 板 | 2 层板直通铜皮没按几安培设计，**会烧** | 它只挂一路的末端或中间 |
| 没有关机检测信号 | 硬断电最伤 microSD | **先软件关机再断电** |

### 5C · `imu_to_dxl` 板（两条路都要）

把 IMU 伪装成 **Dynamixel 从机 ID 200** 挂舵机总线上，让主机一个 tick 只发**一次 `sync_read`** 就同时拿回 IMU 姿态 + 15 个舵机位置，**时间戳天然对齐**（IMU 走 I²C 会和舵机数据差几毫秒，直接污染策略输入）。

**这块板全网无公开工程，必须自己画。** 元件表见 [BOM 清单第 4 节](BOM-采购清单.md)。
**2 层板 · 45 × 22 mm · 两孔间距 34 mm**（可沿用原版打印锁扣）· 打样约 ¥25–40。

**⚠️ 三条硬约束**：
1. LDO 耐压 —— 总线满电 8.4 V，常见型号全不够（AP2112K/ME6211 只有 6.0 V）→ **HT7533-1** 或同级
2. **C6 输入电容 ≥ 25 V**（不是 10 V）—— MLCC 有直流偏压衰减 + 舵机反电动势尖峰
3. **晶振只认「有源晶振 / OSC」标签** —— 3225 四脚无源晶体 2/4 脚是同一片金属盖，贴上**一上电就是 3.3 V 对地短路**

**烧录坑**：STM32G0 空片第一次烧完程序不跑（停在 ST 自带 Bootloader）→ **空片第一次烧完，断电重启一次**（按复位键没用）。

**✅ 验收**：
- [ ] 各段电源逐段量过（先接开关保险丝 → 再降压模块 → 确认极性 → 才插 Radxa）
- [ ] Radxa 靠 pin 2 的 5 V 能点亮并 ssh
- [ ] 单颗舵机 ping 通（1 Mbps）

### 6.1 ⚠️ 先确认你的板子批次

### 6.2 用现成的镜像（最省事）

[GitHub Release](https://github.com/fanhao375/microduck-replica/releases) 上有做好的镜像：

- `20260929 候选版` —— 预置 DHCP、修正首登说明、移除预生成 SSH 主机密钥（**仅离线核验，未烧卡实测**）

> ⚠️ **绿灯双闪可以是正常心跳（`heartbeat`），不是故障码**，结合网络/SSH/日志判断。

### 6.3 或者自己做卡（要预置 WiFi）

用 `tools/radxa/build-armbian-card.sh` + `card.conf`（填 WiFi 名/密码/代理），一键生成带网的卡。

## 阶段 7 · 软件部署

### 7.0 ✅ 走路线 B，直接上 `feetech` 分支（协议已定案）

**结论：HD-1910 用飞特自有 SCS/STS 协议，与 Dynamixel Protocol 2.0 不兼容 —— 必须用 fork。**

已用飞特官方协议手册核实（副本在 `飞特官方文档（doc.feetech.cn）`）：

| | XL330（Protocol 2.0） | HD-1910（飞特 SCS/STS） |
|---|---|---|
| 字头 | **`FF FF FD 00`**（4 字节） | **`FF FF`**（2 字节） |
| 校验 | **CRC-16** | **`~(ID+LEN+INST+参数)`** 取反和 |
| 位置寄存器 | 132 读 / 116 写 | **56 读 / 42 写** |
| 运行模式 | 寄存器 11 = `3` | 寄存器 33 = **出厂 `4`** |
| IMU | 总线 **ID 200** | **总线上没有 IMU** |

> ⚠️ 网上流传的"HD-1910 按 XL330 协议跑、robotd 不用改一行代码"是**错的** ——
> 那是内容农场把 OpenMicroDuck 文档里"官方运行时期望的总线叫 Dynamixel-compatible"误读成了"HD-1910 兼容"。**别信，会白干。**

```bash
git clone -b feetech https://github.com/fanhao375/microduck.git
cd microduck && cargo test -p duck-control -p robotd-params -p robotd
```

| 分支状态 | |
|---|---|
| `bus_feetech.rs` + `bus_select.rs` | ✅ 已完成 |
| 测试 | ✅ 控制库 80 / 参数库 150 / 守护进程 93 全过，`clippy -D warnings` 干净 |
| 交叉编译 aarch64 | ✅ 11 个程序通过，已用开发密钥签名 |
| **上板实测** | ❌ **还没到这一步** |
| **IMU** | ❌ 后端 `imu_ready()` 恒 false → **不启动策略、不做跌倒检测**，暂时只能 `robot init`（2 秒插到站姿） |

**上板 4 步**（同 BOM 8.5 节）：
1. 板子信任开发公钥（`allow_dev_keys = true`）
2. 先用**原版**跑一遍 `robotctl update apply daemon --from`，证明部署链路通（有健康检查，失败自动回滚 0.13.0）

> **整条总线表现为"不通"，现象和接线错一模一样**。先换官方 HAT 或用三态缓冲自动换向再排查。

### 7.1 先确认 `/dev/ttyS2` 就绪

## 阶段 8 · 校准与首走

### 8.1 零位校准

**⚠️ 飞特 HD-1910 不认「扭矩开关写 128」这种中位校准** —— 内存表明写着「写 128：任意当前位置较正为 2048」，照做舵机回「成功」，但**偏移寄存器一个都没变**。固件 3.46 不支持这条。

→ **必须用 `0x0B` 位置校准指令**（不带参数 = 校成 2048，带参数 = 校成指定读数）。
→ **校完一定回读位置和偏移确认，别信应答里的「成功」** —— 飞特很多不支持的操作照样回成功。

⚠️ **校准时别关着扭矩等** —— 扭矩一关关节就被重力压下去，颈部读数掉 80 步（7°），校出来的零位是歪的。
→ **关扭矩到校准完成中间不要 sleep**，几毫秒就够；校准后立刻把目标位置写成新读数再开扭矩。

### 8.2 ⚠️ 方向表：飞特 15 颗全反

**HD-1910 的位置计数方向跟官方 XL330 相反，15 颗全反。**
现象：拖滑块时 3D 模型跟实际反着动；按官方站姿发角度，腿往反方向弯。
→ **15 颗方向全取 −1**（`tools/servo-web/directions.json`，robotd 里是 `[bus.feetech] directions`）。

### 8.3 从"缩起来"到站起来

官方零位是腿伸直，**悬空手扶着摆没有参考点**，一两度就摔。所以先记录一个"缩起来"姿态（扭矩全关、躺着让关节自然垂到底），已在 `tools/servo-web/poses/缩起来-2026-09-17.json`。

**站起来的序列**（`poses/站起来-序列.json`，20 Hz 同步写 + 线性插值）：
1. **抬头 1 s** —— 颈、头 pitch 到 +20°。头占整机**三分之一重量**，趁身子还坐在桌上先摆到站姿位置
2. **展腿脚放平 3 s** —— 膝 +60 / 髋 +30 / 踝 +30（模型约定）。**这一步最关键，第一次托着做**
3. **站直 2 s** —— 沿脚平那条线到官方站姿，脚全程平，身高只涨 10 mm

**几何规律**：`髋 = −26° + 膝/2`，`踝 = +26° + 膝/2`（左腿；右腿全部反号）。
腿太短（大腿 42 mm、小腿 49 mm），膝弯到 +60° 躯干也只降 3 cm。

**重心**：整机 744 g，站姿时重心离脚尖 34 mm、离脚跟 20 mm，半蹲到站姿全程余量 >17 mm。**按模型慢慢站不该往前倒** —— 真机倒了先查**零位偏差**和**电池装没装**。

⚠️ **缩着只能当髋、膝的参考** —— 踝缩着时没被定住（膝髋都折到底后还有约 20° 能动）。
⚠️ 上面这套数是 **XL330 原版几何**，飞特版改过 8 个件，要拿飞特版模型再算或在 SolidWorks 里量。

**✅ 验收**：

- [ ] 方向表逐颗核对过（网页上每颗旁边的 ± 按钮）
- [ ] 托着能完成"缩起来 → 站姿"，无异常阻力
